# Email Studio

A small, password-protected tool for building and storing HTML emails.

- **Edit visually**: click any text in the email and type; bold, italic, links,
  bullets; click a picture to replace it, describe it, link it or remove it.
  No HTML knowledge needed.
- **Edit the code**: switch to **Split** or **Code** to work with the HTML directly
- **Templates**: save, rename, duplicate, delete, search, and organize with tags
- **Masters, drafts and history**: lock the approved version of an email so nobody
  can overwrite it by accident, work in drafts, and restore any earlier version
- **Images**: upload once, get a permanent link (stored in Cloudflare R2)
- **Copy / paste**: one-click "Copy HTML" and "Paste HTML" for the church email tool
- **Checks**: warns about Gmail's ~100 KB clipping, non-https image links, missing alt text

It runs on Cloudflare Pages (free tier). This repository **is** the website:
whatever is on the `main` branch here is what goes live, automatically,
about a minute after each change.

## Using the visual editor (for the whole team)

The **Visual / Split / Code** switch is at the top right of the email. Visual is
the default.

- **Change words:** click the text and type. Select words and use **B**, **I**,
  **U**, **Link** or **• List** in the bar above the email. **Enter** starts a
  new line.
- **Alignment, size, font and color:** click in a paragraph and use the three
  align buttons, or pick a **Size**, **Font**, text color (**A**) or highlight
  (**ab**). Select words to change only those words; with nothing selected, the
  whole paragraph changes. Choose **Email default** to go back to the email's own
  look. **S** is strikethrough, **1. List** makes a numbered list.
  Colors you pick yourself do not adapt in dark mode, so avoid very dark or very
  light colors for important text.
- **Paste text:** from Word, Google Docs or a web page. Fonts, colors and other
  junk are stripped so the email's own design stays intact. Bold, italics and
  links are kept.
- **Change a picture:** click it. A green bar appears with **Choose from
  library**, **Upload new**, a box to describe the picture (alt text, which
  helps accessibility and shows when images are blocked), **Link** and
  **Remove**.
- **Add a picture:** click in the text where it should go, then **+ Picture**
  and **Insert** from the library. While a picture is selected, the library
  offers **Add new** (puts another one right after it) and **Replace** (swaps
  the selected one). Click in the text first to add one somewhere else. You can also drag a picture from the library
  into the email, or paste or drop one from your computer.
- **Big photos are shrunk automatically** to a size that suits email
  (1200 px wide) when uploaded.

What it does **not** do: change the layout itself (add columns, move sections).
Switch to **Split** or **Code** for that, or ask whoever maintains the
templates.

Good to know: after the first visual change to an email, the HTML shown in the
code view is regenerated by the browser, so spacing and line breaks may look
different. The email itself looks and behaves the same.

## Light / Dark preview

Above the preview there is a **Light | Dark** switch. Dark shows the email the way an app in dark mode would, using the email's own dark-mode styles. It only changes the preview, never the email itself, and it works no matter what mode your computer is in. If the email has no dark-mode styles, a note says so. Gmail and Outlook apps do their own recoloring, so this is a close guide, not an exact match. The switch is hidden on a phone.

## Block library

The block library holds sections you want to reuse, like the Elder Spotlight. It is separate from saving your email.

- **Add to Library:** click a section, then choose **Add to Library** in the blue bar and give it a name. This only copies that section into the library. It does not save your email, so press Save for that as usual.
- **+ Block:** in any email, click the section you want it under, choose **+ Block** in the toolbar (next to + Picture), and press **Insert**. The block goes right below that section.
- Remove a block from the library with **Delete** in the same list. Emails that already use it are not changed.

A library block keeps its own colors and classes, so it works best in emails built from the same template (the dark-mode styles live in the email, not the block).

## Moving, copying and deleting sections

Click anywhere inside a section of the email (like the Elder Spotlight) and a blue bar appears above the preview with the section's name. The section is outlined in blue so you can see what you picked.

- **Up / Down** moves the whole section past its neighbor.
- **Duplicate** puts a copy right below it.
- **Delete** removes the whole section. An **Undo** button appears right away and stays until you click somewhere else in the email.

A section is a block that sits in a stack of blocks, which is how your newsletter is built. A comment right above it (like `<!-- Elder Spotlight -->`) moves with it and gives it its name. Deleted sections are also recoverable from History if you saved with them in place.

## Dark mode check

The grey bar under the editor now also checks dark mode. It looks at how your email would appear with the dark-mode styles switched on. If a light block stays bright, or text becomes hard to read, you get "Not dark-mode friendly" and a **Fix for dark mode** button. The button adds dark colors for just those spots and the tags that tell email apps your email supports dark mode. It never changes your own dark-mode styling, and pressing it again changes nothing.

Gmail and Outlook apps do their own color flipping and ignore these styles, so check important emails in a real dark-mode app.

**Adding pictures:** in the visual editor, a picture goes where your cursor is, so click in the text first. If you have a picture selected, you get **Replace** and **Add new** instead. In the Code view, click in the code where you want the picture first. If you haven't, the studio asks you to rather than putting it at the bottom.

## If something goes wrong

- **Refreshing the page** reopens the email you were working on.
- **Unsaved work is backed up on that device.** If the page reloads, the tab
  crashes or the connection drops, open the email again and click **Restore
  them** in the red bar.
- **Two people editing the same email:** if someone saved it after you opened
  it, you're asked before replacing their version. Their version stays in
  **History** either way.
- **A master that looks unchanged:** saving a master creates a draft. A master
  with drafts shows an **Open newest draft** button.
- **Pasted text** is cleaned of colors, fonts and sizes so the email's own look
  (including dark mode) stays in charge.

## Using it on a phone

On a phone the screen is simplified: tap **☰** for your list of emails, **Copy**
and **Save** stay on top, and everything else (Paste HTML, Images, History,
Duplicate, Delete, Make master) is under the **⋯** button. The formatting bar
scrolls sideways. Wide emails are shown shrunk to fit, like a phone mail app
would. **Split** view is hidden because there isn't room; use **Visual** or **Code**.

## Protecting your master templates

- **Make master.** Open a finished email and click **🔒 Make master**. A yellow
  banner appears and the **Save** button becomes **Save as draft**.
- **Saving a master never changes it.** It creates a separate *draft* copy
  ("Name – draft") that sits under the master in the left list. Edit that draft
  as much as you like.
- **Drafts.** Opening a draft shows a blue banner. **Save draft** only changes
  that draft. **Open master** jumps back to the master.
- **When a draft is ready:** click **Replace master with this draft...** (or, on
  the master itself, **Update the master...**). Both ask you to confirm first.
- **History.** Every time an email's content changes, the previous version is
  kept (the latest 20 per email). Click **History**, pick a time, **Load**, then
  Save. Loading never saves by itself. This also rescues a mistaken master update.
- **Deleting a master** is blocked until you click **🔓 Unlock**. The block is
  enforced by the server, not just the button.

## How to update the site (no terminal needed)

### Change one file
1. In this repository on github.com, click through to the file (for example
   `public/index.html`).
2. Click the **pencil icon** (Edit this file) at the top right of the file.
3. Make your change.
4. Click **Commit changes...**, then **Commit changes** again in the box.

### Replace or add several files at once
1. On the repository's main page, click **Add file**, then **Upload files**.
2. Drag in the folders or files. Drag whole folders (like `functions` or
   `public`) so everything lands in the right place. A file with the same path
   as an existing one replaces it.
3. Scroll down and click **Commit changes**.

### Check that it went live
In the Cloudflare dashboard go to **Workers & Pages**, click this project, then
**Deployments**. The top entry should say **Production** and **Success**
within a minute or two. If it says **Failed**, click it to read the log and
send that message to whoever maintains this.

To undo a bad change, open the **Deployments** tab, find an older **Success**
entry, click the three dots, and choose **Rollback to this deployment**.

## What is in this repository

```
public/index.html          the interface (no build step)
public/editor.js           the click-to-edit visual editor
public/darkmode.js         the dark-mode check and fix
functions/_middleware.js   locks /api/* behind the login
functions/_lib/auth.js     password check + signed session cookie
functions/_lib/tags.js     rules for template tags
functions/_lib/versions.js saved earlier versions (history)
functions/api/*            login, templates (KV), block library (KV), images (R2)
functions/img/[key].js     public image links used inside emails
wrangler.toml              project settings and storage connections
```

`wrangler.toml` is the source of truth for the storage connections (KV for
templates, R2 for images). Those can't be edited in the Cloudflare dashboard,
only here.

**The password is never in this repository.** It is a Cloudflare secret named
`APP_PASSWORD` (see below). Never paste it into any file here.

## First-time setup (already done if the site is running)

1. **Storage.** In the Cloudflare dashboard: *Storage & Databases* then
   *KV* to create a namespace named `TEMPLATES` and copy its **ID** into
   `wrangler.toml`; *R2 Object Storage* to create a bucket named
   `email-images`. (R2 may ask for a payment card to enable it; the free
   allowance is large.)
2. **Connect this repository.** Workers & Pages, *Create application*,
   *Pages*, *Connect to Git*, pick this repository. Settings: framework
   preset **None**, build command **empty**, build output directory
   **`public`**.
3. **Set the password.** Project, *Settings*, *Variables and Secrets*,
   *Add*, type **Secret**, name `APP_PASSWORD`, then enter the password.
   Save it in your password manager too; Cloudflare won't show it again.
4. **Redeploy** (Deployments tab, three dots on the top entry, *Retry
   deployment*) so the password takes effect. Secrets only apply to
   deployments made after they are set.
5. **Custom address (recommended).** Project, *Custom domains*, add something
   like `email.yourchurch.org`, then in `wrangler.toml` uncomment `[vars]` and
   set `PUBLIC_BASE_URL = "https://email.yourchurch.org"`.
   Image links in sent emails are tied to the address the image was uploaded
   from, so set this up **before** uploading real images and never change it.

**To change the password:** edit the `APP_PASSWORD` secret in the dashboard,
then retry the latest deployment. Everyone is logged out automatically.

## Security notes

- The password is a Cloudflare secret, compared in constant time; sessions are
  signed cookies (HttpOnly, SameSite=Strict, 30 days).
- Only `/img/*` links are public, because email apps must load them. Anyone
  with an image link can view that image, but nobody can list, upload or
  delete without the password.
- Uploads are checked by their real file contents (PNG/JPG/GIF/WebP only).
  SVG is intentionally not allowed because most email apps don't show it.
- Keep this repository **private**.

## Backups

Templates are just text: use **Copy HTML** on anything important and keep a
copy in Google Drive. Images can be exported from the R2 bucket in the
Cloudflare dashboard.

## Optional: running it on your own computer

Only for people comfortable with a terminal. Needs Node.js.

```bash
npm install
cp .dev.vars.example .dev.vars    # throwaway local password
npm run dev
```

Local mode uses temporary fake storage, so it never touches real data.
